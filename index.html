A base que cai em toda questão

Começa pela moldura que o professor montou no func1.cpp — os quatro tipos de função. Toda questão da prova é um desses quatro casos, com recursão por dentro.

Os 4 tipos de função

TipoRecebe?Devolve?Exemplo da aulaNos seus exercícios
1ºnãonão void escreve(void)—
2ºsimnão void soma(int a, int b) preencherVetor, exibirVetor, encontrarMaior, buscarValor

Repare no padrão das suas entregas: quando a função tem um resultado numérico, ela é do 3º tipo e usa return. Quando precisa entregar dois ou mais — o maior valor e a posição, ou o contador que sobe a cada ocorrência — ela vira do 2º tipo e devolve pelo parâmetro por referência. Saber justificar essa escolha é exatamente o tipo de pergunta que a prova faz.

ORDEM Função antes da main

Tanto o professor quanto os seus arquivos definem as funções acima da main, sem protótipo. Funciona porque, quando a main chama, a função já foi lida.

#include <iostream>
using namespace std;

int somaRecursiva(...) {   // primeiro as funções
    ...
}
int main() {               // depois a main
    ...
}

PARÂMETRO As três passagens

Por valor a função recebe cópia e não altera nada. Por ponteiro ou por referência ela altera o original — você usou referência nos exercícios 2 e 4.

void vlr(int x)  { x = x*2; }   // não muda  
void ptr(int *x) { *x = *x*2; } // muda      
void ref(int &x) { x = x*2; }   // muda      

vlr(v);    // v continua 5
ptr(&v);   // v virou 10  
ref(v);    // v virou 20

PONTEIRO Os três símbolos

int *p declara. &x é o endereço de x. *p é o valor guardado nesse endereço. O int *mat dos seus exercícios 3 e 4 é exatamente isso.

int x = 7;
int *p = &x;   // p aponta para x
*p = 9;        // x agora vale 9
p++;           // anda 1 int adiante

VETOR Já é um ponteiro

O nome do vetor é o endereço do primeiro elemento. Por isso somaRecursiva(numeros, 10, 0) não leva &, e o que a função escreve em vetor[i] vale lá fora.

void f(int v[], int n);  // idênticos
void f(int *v, int n);

preencherVetor(numeros, 10, 0);
// v[i]  ==  *(v + i)

RECURSÃO Duas partes, sempre

Caso base: quando parar e o que devolver. Chamada recursiva: resolve um pedacinho e chama a si mesma com o problema menor. Sem o base, estouro de pilha.

int fatorial(int n){
	if(n==0)//caso base ou trivial
		return 1;
	return n*fatorial(n-1);//chamada recursiva
}

BASE VOID Parar sem devolver

Numa função void o caso base é só return; — sem valor nenhum. É o padrão dos seus preencherVetor, exibirVetor, encontrarMaior e buscarValor.

void preencherVetor(int v[], int tam, int ind) {
    if (ind == tam) {
        return;          // para aqui
    }
    v[ind] = rand() % 10;
    preencherVetor(v, tam, ind + 1);
}
02

A matriz achatada — o seu jeito

Este é o ponto mais técnico da matéria e você já resolveu ele nos exercícios 3 e 4. Vale entender a fundo, porque é a explicação mais provável de cair na prova.

O problema: a ordem da matriz só é conhecida quando o programa roda, mas para passar uma matriz a uma função o C++ exige saber o tamanho da linha em tempo de compilação. int f(int m[][], int n) não compila.

A sua solução: passar &mat[0][0] — o endereço do primeiro elemento — como um int *mat comum, e calcular a posição na mão. A matriz deixa de ser bidimensional para a função e vira uma fila única de ordem*ordem números.

// na main
cin>>ordem;
int mat[ordem][ordem];

// na chamada — &mat[0][0] é o endereço do primeiro elemento
sp = somaDiagonalPrincipal(&mat[0][0], ordem, 0);

// na função — um ponteiro simples, sem dimensão nenhuma
int somaDiagonalPrincipal(int *mat, int ordem, int indice){
	...
	return mat[indice*ordem+indice] + ...
}

As duas fórmulas, que são uma só

SentidoFórmulaOnde você usou
(linha, coluna) → posição k = linha*ordem + coluna Exercício 3 — mat[indice*ordem+indice]
posição → (linha, coluna) linha = k/ordem
coluna = k%ordem		 Exercício 4 — para imprimir onde achou

Uma é o inverso da outra. Numa matriz 4×4, a casa (2,1) está na posição 2*4+1 = 9 da fila; e a posição 9 volta a ser linha 9/4 = 2, coluna 9%4 = 1. É o mesmo cálculo que o compilador faria sozinho se ele soubesse o tamanho da linha — você só está fazendo à mão o que ele não pode fazer quando a ordem é digitada.

Uma ressalva honesta sobre int mat[ordem][ordem]: declarar a matriz com um tamanho que só existe em tempo de execução é uma extensão do compilador g++ (herdada do C), não C++ padrão. Funciona no compilador da disciplina e foi assim que você entregou — só não se assuste se algum outro compilador reclamar. A alternativa é declarar com um teto fixo: const int MAX=20; int mat[MAX][MAX];. O truque do &mat[0][0] continua funcionando igual nos dois casos, desde que ordem seja o número de colunas realmente usadas na declaração — se você declarar com MAX, o passo entre linhas passa a ser MAX, e a conta vira mat[linha*MAX+coluna].

Gabarito

1void2return3104NULL5mult(x,y)

O que o código faz: demonstra os quatro tipos de função. Escreve uma frase, soma e imprime, multiplica e devolve, e sorteia um número de 0 a 9.

soma × mult: as duas recebem a e b e calculam. A diferença é o destino do resultado. soma é void: imprime ali mesmo e o valor se perde — a main não consegue reaproveitá-lo. mult é int: devolve com return, e por isso a main precisa de uma variável (mu) para guardar o que voltou. Guardar o valor é o que permite usá-lo depois numa conta, numa comparação ou noutra função.

void nos dois lugares: antes do nome significa "não devolve nada". Dentro dos parênteses, como em escreve(void), significa "não recebe nada" — em C++ também se pode deixar os parênteses vazios.

srand(time(NULL)): alimenta o sorteador com o relógio, para os números mudarem a cada execução. Sem ele, rand() devolve sempre a mesma sequência. Vai uma vez só, no início da main — exatamente como nos seus quatro exercícios.

02

De iterativo para recursivo

fatit.cpp · fatrecurs.cpp

À esquerda o fatorial com while, à direita o mesmo fatorial em recursão. Explique o que, na versão recursiva, faz o papel do while.

//---------- versao iterativa (fatit.cpp) ----------
int fatorial(int n){
	int fat = 1;
	while(n>1){
		fat *= n;
		n--;
	}
	return fat;
}

//---------- versao recursiva: complete ----------
int fatorial(int n){
	if(n==1)//caso base ou trivial
		return 2;
	return n*fatorial(3);//chamada recursiva
}

Gabarito

10213n - 1

O que o código faz: lê um número e devolve o fatorial dele. As duas versões dão o mesmo resultado por caminhos diferentes.

Quem substitui o while: a própria chamada recursiva. No iterativo, a condição n>1 decide se repete e n-- faz o valor andar. No recursivo, o if(n==0) decide se para e o argumento n-1 faz o valor andar. É a mesma engrenagem — condição de parada e avanço — escrita de outro jeito. Foi exatamente essa troca que você fez nos exercícios: o for que preencheria o vetor virou o parâmetro indice.

Quem substitui a variável fat: ninguém. O acumulador desaparece: os produtos ficam guardados nas chamadas empilhadas e são multiplicados na volta — 4*(3*(2*(1*1))). Isso é o que se ganha e o que se paga na recursão: código mais curto, mas consumo de pilha proporcional a n.

Por que n==0 e não n==1: as duas param, mas n==0 também cobre fatorial(0), que por definição vale 1. Com n==1, chamar fatorial(0) passaria direto e a função desceria para −1, −2, −3… até estourar a pilha. Testar n<=1 resolve os dois de uma vez e é resposta igualmente aceitável.

Potência sem usar pow

func1.cpp · exercício pendente

O exercício que ficou comentado no fim do func1.cpp: eleva(y,x) eleva a base y ao expoente x. Explique por que o caso base devolve 1 e não 0.

//eleva a base ao expoente sem utilizar o pow()
int eleva(int base, int expo){
	if(expo==1)//caso base ou trivial
		return 2;
	return base*eleva(base,3);//chamada recursiva
}

Gabarito

10213expo - 1

O que o código faz: calcula 5³ = 125 multiplicando a base por ela mesma, uma vez a cada chamada, até o expoente zerar.

O caso base devolve 1 por dois motivos que se encaixam: matematicamente, qualquer número elevado a 0 é 1; e 1 é o elemento neutro da multiplicação, então não estraga o produto que está sendo montado na volta. Devolver 0 zeraria tudo — 5*5*5*0 = 0.

Compare com o seu Exercício 1, onde o caso base devolve 0. A regra geral vale para qualquer recursão que acumula: o caso base devolve o neutro da operação. Soma e contagem → 0. Produto e potência → 1.

O que faz o problema diminuir: expo-1. A base fica igual em todas as chamadas; quem encolhe é o expoente.

O outro exercício pendente do arquivo — raiz(y) — não é recursivo: basta #include<cmath> e return sqrt(y); numa função do 3º tipo.

Soma dos elementos de um vetor

Exercício 1 · Lista Q1

Três funções recursivas: uma preenche, uma exibe e uma soma. Nenhum laço no programa inteiro. Explique por que preencherVetor é void e somaRecursiva é int.

#include <iostream>
#include <cstdlib>
#include <ctime>
using namespace std;

void preencherVetor(int vetor[], int tamanho, int indice) {
    if (indice == 1) {
        return;
    }
    vetor[indice] = rand() % 2; // numero aleatorio entre 0 e 9
    preencherVetor(vetor, tamanho, 3);
}

int somaRecursiva(int vetor[], int tamanho, int indice) {
    if (indice == tamanho) {
        return 4;
    }
    return vetor[indice] + somaRecursiva(vetor, tamanho, 5);
}

void exibirVetor(int vetor[], int tamanho, int indice) {
    if (indice == tamanho) {
        cout << endl;
        return;
    }
    cout << vetor[indice] << " ";
    exibirVetor(vetor, tamanho, indice + 1);
}

int main() {
    int tamanhoVetor = 10;
    int numeros[10];
    int resultadoSoma;

    srand(time(6));
    preencherVetor(numeros, tamanhoVetor, 7);

    cout << "Vetor: ";
    exibirVetor(numeros, tamanhoVetor, 0);

    resultadoSoma = somaRecursiva(numeros, tamanhoVetor, 0);
    cout << "Resultado da soma: " << resultadoSoma << endl;

    return 0;
}

Gabarito

1tamanho2103indice + 1405indice + 16NULL70

O que o código faz: preenche um vetor de 10 posições com inteiros de 0 a 9, exibe o vetor e devolve a soma — as três coisas por recursão, sem nenhum for.

void × int: preencherVetor não tem um resultado para devolver — o trabalho dela é escrever dentro do vetor, e essas escritas já ficam visíveis para a main porque vetor é passado por endereço. somaRecursiva produz um número único, que só chega à main pelo return. Regra prática: se o resultado é um valor, use return; se o resultado é uma alteração num vetor ou matriz, void basta.

Caso base das três: é o mesmo — indice == tamanho, ou seja, o índice passou do último elemento válido (tamanho-1). Nas void ele é só return;; na int tem de devolver 0, o neutro da soma, senão o total sai errado.

O índice como substituto do laço: o parâmetro indice faz o papel do i de um for. Cada chamada avança uma posição, e a primeira chamada sempre parte de 0.

Detalhe do exibirVetor: o cout << endl está dentro do caso base, não depois do laço — é ali que a linha se fecha, quando não há mais elemento para imprimir. Boa resposta curta para "por que o endl está nesse lugar?".

O que o código faz: gera 15 reais na faixa pedida e descobre o maior deles junto com a posição em que aparece pela primeira vez.

Dois resultados sem return: a função é void, mas double &maiorValor e int &posicaoMaior são referências — apelidos para as variáveis da main. Escrever maiorValor = vetor[indice] dentro da função altera a variável lá fora. É assim que uma função entrega mais de um resultado. Com ponteiro seria double *maiorValor e *maiorValor = vetor[indice], com &maiorValor na chamada — mesmo efeito, mais símbolos.

Por que > garante a primeira ocorrência: a varredura vai da esquerda para a direita e só substitui o campeão quando encontra alguém estritamente maior. Num empate, a condição é falsa, nada é atualizado e a posição guardada continua sendo a do primeiro. Se fosse >=, cada empate sobrescreveria a posição e você terminaria com a última ocorrência — resposta errada para o enunciado. É por isso que a lacuna 5 vale a questão inteira.

Por que começa em 1: maiorValor e posicaoMaior já foram inicializados com o elemento 0, então ele já está considerado. Começar do 0 não daria erro, só repetiria uma comparação. O que não pode é inicializar maiorValor com 0: num vetor só de negativos, nenhum elemento seria maior e a resposta sairia errada.

A faixa de reais: rand()/RAND_MAX dá um número entre 0 e 1 — daí o nome fracaoAleatoria. Multiplicado pela amplitude (25.7 − 12.3) e somado ao mínimo, o resultado cai dentro de [12.3, 25.7]. O (double) na frente é essencial: sem ele a divisão seria inteira e daria sempre 0.

Soma das duas diagonais

Exercício 3 · Lista Q3

Matriz de ordem digitada, valores de 4 a 12, as duas diagonais por recursão. Explique o que é &mat[0][0] e por que a função recebe int *mat em vez de uma matriz.

int somaDiagonalPrincipal(int *mat, int ordem, int indice){
	if(indice==1)
		return 2;
	return mat[indice*ordem+3] + somaDiagonalPrincipal(mat,ordem,4);
}

// diagonal secundaria: linha + coluna == ordem-1
int somaDiagonalSecundaria(int *mat, int ordem, int indice){
	if(indice==ordem)
		return 0;
	return mat[indice*ordem+(5)] + somaDiagonalSecundaria(mat,ordem,indice+1);
}

int main(){
	int ordem,i,j,sp,ss;
	cout<<"Informe a ordem da matriz (4 a 12): ";
	cin>>ordem;

	int mat[ordem][ordem];
	srand(time(NULL));

	for(i=0;i<ordem;i++)
		for(j=0;j<ordem;j++)
			mat[i][j] = rand()%6 + 4; //faixa de 4 a 12

	for(i=0;i<ordem;i++)
	{
		for(j=0;j<ordem;j++)
			cout<<setw(3)<<mat[i][j]<<"  ";
		cout<<"\n";
	}

	sp = somaDiagonalPrincipal(7,ordem,0);
	ss = somaDiagonalSecundaria(&mat[0][0],ordem,0);

	cout<<"\nSoma da diagonal principal: "<<sp<<endl;
	cout<<"Soma da diagonal secundaria: "<<ss<<endl;
}

Gabarito

1ordem203indice4indice + 15ordem - 1 - indice697&mat[0][0]

O que o código faz: lê a ordem, preenche a matriz com inteiros de 4 a 12, exibe em formato de matriz e soma as duas diagonais com duas funções recursivas.

O que é &mat[0][0]: o endereço do primeiro elemento da matriz. Como os elementos estão guardados na memória em sequência, linha após linha, esse endereço é o começo de uma fila de ordem*ordem inteiros. A função recebe esse ponteiro e passa a tratar tudo como se fosse um vetor comum.

Por que int *mat e não uma matriz: para escrever int mat[][N] no parâmetro, o compilador precisa do número de colunas em tempo de compilação — e aqui a ordem só é conhecida depois do cin. Passando um ponteiro simples, você contorna a exigência e faz a conta do endereço à mão.

A fórmula indice*ordem+coluna: pule indice linhas inteiras (cada uma com ordem elementos) e depois ande coluna casas. Na diagonal principal, linha e coluna são iguais, então vira indice*ordem+indice. Na secundária, linha + coluna = ordem − 1, logo a coluna é ordem-1-indice. Confira com ordem 4: as posições são (0,3), (1,2), (2,1), (3,0) — em todas a soma dá 3.

Erro clássico na secundária: escrever ordem-indice. Com indice=0 isso apontaria para a coluna ordem, que não existe — e, numa matriz achatada, o programa leria silenciosamente o primeiro elemento da linha seguinte, sem travar. Bug difícil de enxergar.

A faixa 4 a 12: são 12 − 4 + 1 = 9 valores possíveis, então rand()%9 + 4.

Se a ordem for ímpar: o elemento central pertence às duas diagonais e é contado nas duas somas. Não é erro — mas é a pergunta extra que o professor pode fazer.

1&2ordem*ordem3/4%5++6k + 170

O que o código faz: percorre as ordem*ordem casas da matriz, imprime a linha e a coluna de cada ocorrência do valor procurado e devolve o total pelo contador.

Um índice para duas dimensões: k é a posição na fila única de elementos. A linha é k/ordem — a divisão inteira conta quantas linhas completas já passaram — e a coluna é k%ordem, o resto, que diz quanto se andou dentro da linha atual. Numa matriz 5×5, k=7 vira linha 1, coluna 2. Esse par de operações produz exatamente o percurso que o enunciado pede: coluna a coluna, pulando de linha quando a atual acaba.

É o inverso do Exercício 3: lá você tinha linha e coluna e calculava a posição (indice*ordem+indice); aqui você tem a posição e calcula linha e coluna. Mesma ideia, sentidos opostos — e essa comparação é ótima resposta de prova.

Por que int &contador: a função é void e precisa que o total sobreviva às chamadas e chegue à main. Como referência, contador++ incrementa a variável original. Se o & fosse esquecido, cada chamada incrementaria a própria cópia, a main receberia 0 e o programa sempre diria "não foi encontrado" — o erro mais caro que essa questão permite.

mat[k] direto: como k já é a posição na fila, não é preciso recalcular nada para ler o elemento. Linha e coluna só são calculadas para exibir a posição ao usuário.

Mensagem de "não encontrado": quem decide é a main, testando contador==0. A função recursiva só conta e imprime as ocorrências — cada parte do programa com uma responsabilidade, que é o que o enunciado pede ao mandar organizar em funções.

	*a  = 2;
	*b  = aux;
}

int main(){
	int x=10,y=20;
	troca(3,4);
	cout<<x<<" "<<y<<endl;//20 10
}

Gabarito

1*a2*b3&x4&y

O que o código faz: troca o conteúdo de duas variáveis da main, usando uma auxiliar para não perder o primeiro valor.

Por que precisa de aux: se você escrevesse *a = *b direto, o valor original de a seria sobrescrito e não haveria como recuperá-lo.

Se fosse por valor: a função receberia cópias. A troca aconteceria de verdade, mas só dentro dela — ao voltar para a main, x e y continuariam 10 e 20.

Ponteiro × referência, lado a lado: a versão com referência é void troca(int &a, int &b), corpo aux=a; a=b; b=aux; e chamada troca(x,y) — foi o estilo que você usou nos Exercícios 2 e 4. As duas fazem exatamente a mesma coisa; a referência esconde os símbolos, o ponteiro os deixa à mostra. Se a prova pedir ponteiro, é esta versão; se pedir só "alterar os valores", qualquer uma serve — e saber explicar a equivalência costuma valer ponto.

Menor e maior na mesma varredura

Ponteiros + recursão

O seu encontrarMaior reescrito com ponteiro e devolvendo dois resultados. Explique por que dentro da função o valor é *menor e não menor.

void minMax(int v[], int tamanho, int indice, int *menor, int *maior){
	if(indice==tamanho)
		return;

	if(v[indice] < 1)
		*menor = v[indice];

	if(v[indice] > *maior)
		2 = v[indice];

	minMax(v,tamanho,3,menor,maior);
}

// --- na main ---
int menor=numeros[0],maior=numeros[0];
minMax(numeros,tamanhoVetor,1,4,5);

Gabarito

1*menor2*maior3indice + 14&menor5&maior

O que o código faz: varre o vetor uma vez só e atualiza, pelos ponteiros, as variáveis menor e maior que vivem na main.

*menor × menor: o parâmetro int *menor guarda um endereço. Comparar v[indice] < menor seria comparar um número com um endereço — o compilador reclama, e mesmo que passasse não teria sentido. O asterisco é o que abre o pacote: *menor é o valor guardado naquele endereço. Compare com a versão por referência do seu Exercício 2, onde maiorValor já é o valor e não leva símbolo nenhum.

Por que os dois começam em numeros[0]: inicializar com 0 quebraria num vetor só de negativos (nada seria menor que 0 do lado do maior) ou só de positivos. Partindo de um elemento real, a comparação sempre faz sentido — mesma decisão que você tomou no Exercício 2.

Por que a chamada parte do índice 1: o elemento 0 já entrou como valor inicial.

Soma do vetor andando com o ponteiro

Aritmética de ponteiros

A mesma soma do Exercício 1, sem índice nenhum: quem anda é o ponteiro. Explique a diferença entre p+1 e *p+1.

int somaPtr(int *p, int tamanho){
	if(tamanho==0)
		return 0;
	return 1+somaPtr(2,3);
}

// --- na main ---
cout<<"Soma = "<<somaPtr(numeros,10)<<endl;// sem &: vetor ja e endereco

Gabarito

1*p2p + 13tamanho - 1

O que o código faz: soma tamanho inteiros a partir do endereço p. Em vez de avançar um índice, avança o próprio ponteiro e diminui quanto falta.

p+1 × *p+1: p+1 é o endereço do próximo inteiro — o compilador soma sizeof(int) bytes, não 1 byte. Já *p+1 é o valor apontado mais um. Trocar um pelo outro é erro de prova garantido.

Duas coisas mudam juntas: o ponteiro anda e o tamanho encolhe. Se só o ponteiro andasse, o caso base nunca chegaria; se só o tamanho encolhesse, a função somaria o primeiro elemento várias vezes.

Por que não leva &: o nome do vetor já é o endereço do primeiro elemento. numeros e &numeros[0] são a mesma coisa — e é por isso que, na matriz dos Exercícios 3 e 4, você precisou escrever &mat[0][0]: ali você quer o endereço do primeiro int, não o da primeira linha.

Equivalência útil: v[i] é literalmente *(v+i). As duas versões da soma fazem a mesma coisa; a prova pode pedir qualquer uma.

Inverter o vetor no lugar

Vetores + recursão

Dois índices caminhando um em direção ao outro. Explique por que o vetor sai invertido mesmo a função sendo void.

void inverte(int vetor[], int inicio, int fim){
	if(inicio>=1)
		return;

	int aux = vetor[inicio];
	vetor[inicio] = vetor[fim];
	vetor[fim] = aux;

	inverte(vetor,2,3);
}

// --- na main ---
inverte(numeros,0,4);

Gabarito

1fim2inicio + 13fim - 14tamanhoVetor - 1

O que o código faz: troca o primeiro com o último, o segundo com o penúltimo, e assim por diante, até os índices se encontrarem no meio. O vetor fica invertido sem precisar de um segundo vetor.

Caso base inicio>=fim: cobre os dois finais possíveis. Com tamanho par, os índices se cruzam (inicio>fim); com tamanho ímpar, eles se encontram no elemento do meio (inicio==fim), que não precisa trocar com ninguém. Usar só inicio==fim deixaria o caso par passar direto e a recursão sairia dos limites do vetor.

Void mas altera: int vetor[] é um ponteiro para o vetor original — não existe cópia. Toda escrita acontece na memória da main. É a mesma razão pela qual o seu preencherVetor funciona sendo void; e é por isso que contador, que é um int solto, precisou do & no Exercício 4.

Último índice é tamanhoVetor-1: um vetor de 10 posições vai de 0 a 9.

Soma total da matriz com duas recursões

Matrizes

Uma função soma uma linha; a outra soma todas as linhas. Explique a diferença desta abordagem para a do índice único do Exercício 4.

int somaLinha(int *mat, int ordem, int linha, int coluna){
	if(coluna==ordem)
		return 0;
	return mat[linha*ordem+coluna] + somaLinha(mat,ordem,linha,1);
}

int somaMatriz(int *mat, int ordem, int linha){
	if(linha==ordem)
		return 0;
	return somaLinha(mat,ordem,linha,2) + somaMatriz(mat,ordem,3);
}

Gabarito

1coluna + 1203linha + 1

O que o código faz: devolve a soma de todos os elementos da matriz. somaMatriz cuida das linhas, somaLinha cuida das colunas de uma linha.

Cada função tem seu caso base: somaLinha para quando coluna==ordem; somaMatriz para quando linha==ordem. São duas recursões independentes, uma chamando a outra.

A lacuna 2 é a pegadinha: somaLinha precisa recomeçar do zero em cada linha nova. Passar linha ali faria a soma pular colunas.

Comparado ao índice único: o k do Exercício 4 resolve tudo numa função só. Esta versão é mais longa, mas aproveita a estrutura de linhas — é o caminho quando a prova pede algo por linha: a soma de cada linha, a média de cada linha, a maior linha. As duas atendem à exigência de não usar laço.

13

Busca binária recursiva

Vetores + recursão

Busca em vetor ordenado. Explique por que ela só funciona ordenado e o que devolve quando não acha.

int buscaBinaria(int vetor[], int inicio, int fim, int chave){
	if(inicio>fim)
		return 1;

	int meio = (inicio+fim)/2;

	if(vetor[meio]==chave)
		return 2;

	if(chave<vetor[meio])
		return buscaBinaria(vetor,inicio,3,chave);

	return buscaBinaria(vetor,4,fim,chave);
}

Gabarito

1-12meio3meio - 14meio + 1

O que o código faz: procura chave olhando o elemento do meio e descartando metade do vetor a cada chamada. Devolve o índice onde encontrou, ou −1.

Por que precisa estar ordenado: a decisão de ir para a esquerda ou para a direita só é confiável se tudo antes do meio for menor e tudo depois for maior. Em vetor desordenado, a metade descartada poderia conter a chave.

Por que −1: índices válidos vão de 0 para cima, então −1 é impossível e serve como sinal de "não encontrado". Devolver 0 seria ambíguo — 0 é uma posição real. Compare com o seu Exercício 4, que resolveu o mesmo problema de outro jeito: lá o sinal de "não achou" é o contador em 0.

Os ±1 importam: o elemento do meio já foi testado e não é a chave, então fica de fora das duas faixas seguintes. Escrever meio em vez de meio-1 faz a faixa nunca encolher quando a chave não existe — recursão infinita.

Ganho: a cada chamada o problema cai pela metade. Num vetor de 1000 posições, no máximo 10 chamadas; a busca linear faria 1000.

04

Só explique: o que este código faz?

Nada para completar. Leia, simule na mão com o valor sugerido, escreva a resposta e confira. É o segundo tipo de questão da prova.

T1

Simule com f(472)

int f(int n){
	if(n==0)
		return 0;
	return n%10+f(n/10);
}

Resposta

Soma os dígitos do número. n%10 extrai o último dígito, n/10 remove esse dígito. A recursão vai comendo o número pela direita até sobrar 0.

f(472) = 2 + f(47) = 2 + 7 + f(4) = 2 + 7 + 4 + f(0) = 13.

Repare que é o mesmo par / e % do seu Exercício 4 — lá separando linha de coluna, aqui separando os dígitos.

T2

Simule com g(10)

void g(int n){
	if(n==0)
		return;
	g(n/2);//chamada ANTES do cout
	cout<<n%2;
}

Resposta

Imprime o número em binário. g(10) escreve 1010.

O detalhe que a prova quer: o cout vem depois da chamada recursiva, então nada é impresso na ida — as chamadas empilham até n virar 0 e a impressão acontece na volta, invertendo a ordem dos restos. Se o cout viesse antes, sairia 0101.

Compare com o seu exibirVetor, onde o cout vem antes da chamada: por isso ele imprime na ordem certa, do índice 0 ao último.

T3

O que h devolve?

int h(int v[], int n, int i, int x){
	if(i==n)
		return 0;
	return (v[i]==x)+h(v,n,i+1,x);
}

Resposta

Conta quantas vezes o valor x aparece no vetor. A comparação (v[i]==x) devolve true ou false, que viram 1 e 0 na soma — então ela soma 1 a cada acerto.

É o mesmo objetivo do seu Exercício 4, por outro caminho: lá o total sobe num int &contador por referência; aqui ele sobe no próprio return, sem parâmetro extra. Vale como resposta a "dá para contar sem usar referência?" — dá, se a função puder devolver valor.

T4

O que acontece com a matriz?

void t(int *mat, int ordem, int linha, int coluna){
	if(linha==ordem) return;
	if(coluna==ordem){ t(mat,ordem,linha+1,0); return; }

	if(linha<coluna){
		int aux = mat[linha*ordem+coluna];
		mat[linha*ordem+coluna] = mat[coluna*ordem+linha];
		mat[coluna*ordem+linha] = aux;
	}
	t(mat,ordem,linha,coluna+1);
}

Resposta

Transpõe a matriz — troca linhas por colunas, refletindo tudo em torno da diagonal principal.

Dois detalhes valem ponto. O if(coluna==ordem) é o "pulo de linha": zera a coluna e avança a linha — o mesmo percurso do seu Exercício 4, só que com dois índices em vez de um k. E o if(linha<coluna) garante que cada par seja trocado uma única vez: sem ele, o par (0,1) seria trocado e depois destrocado em (1,0), e a matriz voltaria ao que era.

Repare que mat[coluna*ordem+linha] é a fórmula com os papéis invertidos — é exatamente o que "transpor" significa.

T5

O que é impresso?

void a(int x){ x = x*2; }
void b(int *x){ *x = *x*2; }
void c(int &x){ x = x*2; }

int main(){
	int v = 5;
	a(v);   cout<<v<<" ";
	b(&v);  cout<<v<<" ";
	c(v);   cout<<v<<endl;
}

Resposta

Imprime 5 10 20.

a recebe uma cópia: dobra a cópia, a cópia morre no fim da função e v continua 5. b recebe o endereço e *x = *x*2 escreve na variável da main, que vira 10. c recebe uma referência — outro nome para a mesma variável — e chega ao mesmo resultado sem * nem & na chamada, dobrando para 20.

A pegadinha é a terceira: c(v) parece passagem por valor, mas o & na declaração do parâmetro muda tudo. É o seu int &contador do Exercício 4 — sempre olhe a assinatura da função, não a chamada.

T6

Por que &mat[0][0] e não mat?

int mat[ordem][ordem];

f(&mat[0][0], ordem, 0);   // assim voce entregou
f(mat, ordem, 0);           // e assim?

Resposta

Os dois apontam para o mesmo byte, mas têm tipos diferentes — e é o tipo que o compilador checa.

&mat[0][0] é o endereço de um int, ou seja, do tipo int * — exatamente o que o parâmetro pede. Já mat sozinho é o endereço da primeira linha, do tipo "ponteiro para vetor de ordem inteiros". Passar um no lugar do outro dá erro de compilação, mesmo o endereço numérico sendo idêntico.

Resposta curta para a prova: &mat[0][0] converte a matriz num ponteiro simples para o primeiro elemento, que é o que permite tratá-la como uma fila única e calcular a posição com linha*ordem+coluna.

05

Os erros que mais custam ponto

Cada um destes já apareceu em alguma questão acima. Passe os olhos na véspera.

  • Esquecer o & no parâmetro de saídaO caso mais caro. void buscarValor(..., int contador) compila normalmente, mas cada chamada incrementa a própria cópia — a main recebe 0 e o programa sempre diz "não encontrado". O certo é int &contador (ou int *contador).
  • Esquecer o caso baseA função chama a si mesma para sempre até a pilha estourar. Escreva o if de parada antes da chamada recursiva, sempre.
  • Caso base que nunca é alcançadoreturn n*fatorial(n); em vez de return n*fatorial(n-1); — o problema precisa diminuir a cada chamada. Na recursão com ponteiro, duas coisas mudam juntas: p+1 e tamanho-1.
  • Devolver o valor errado no caso baseSoma e contagem devolvem 0; produto e potência devolvem 1; busca binária que não achou devolve -1. Em função void, o caso base é só return;.
  • >= onde devia ser >Na varredura da esquerda para a direita, > mantém a primeira ocorrência do maior; >= sobrescreve a cada empate e entrega a última. O enunciado pede a primeira.
  • Errar a fórmula da diagonal secundáriaÉ ordem-1-indice, nunca ordem-indice. E numa matriz achatada o erro não trava o programa: ele lê o primeiro elemento da linha seguinte e o resultado sai errado em silêncio.
  • Confundir *p com pDentro da função, o valor é *menor; menor sozinho é o endereço. E p+1 anda uma posição, *p+1 soma um ao valor.
  • Passar mat onde o parâmetro é int *Tem de ser &mat[0][0]. Os dois apontam para o mesmo lugar, mas só um tem o tipo certo.
  • Divisão inteira sem perceberrand()/RAND_MAX dá 0 porque os dois são inteiros — daí o (double) na frente no Exercício 2. Mesma armadilha numa média: use (double)soma/total.
  • Inicializar o maior com 0Num vetor de negativos nada seria maior. Inicialize com vetor[0] e comece a varredura do índice 1.
  • Estourar os limitesUm vetor de 10 vai de 0 a 9; o último índice é tamanho-1.
  • Esquecer os #include<iostream> para cin/cout, <iomanip> para setw, <cstdlib> para rand, <ctime> para time, <cmath> para sqrt.
  • Chamar srand(time(NULL)) dentro do laço ou da recursãoUma vez só, no começo da main. Repetido, todos os sorteios saem iguais.
  • Laço dentro da função recursivaO enunciado proíbe. Se apareceu um for lá dentro, transforme o contador do laço em parâmetro — foi exatamente o que você fez com indice e com k.
