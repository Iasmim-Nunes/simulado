A base que cai em toda questão

Começa pela moldura que o professor montou no func1.cpp — os quatro tipos de função. Toda questão da prova é um desses quatro casos, com recursão por dentro.

Os 4 tipos de função

As funções recursivas da lista são quase todas do 3º tipo — recebem o vetor ou a matriz, o tamanho e um índice de controle, e devolvem um número. As duas exceções são a de troca e a de mínimo/máximo, que devolvem pelo ponteiro e por isso são do 2º tipo.

ORDEM Função antes da main

O professor define as funções acima da main e não usa protótipo. Funciona porque, quando a main chama, a função já foi lida. Protótipo só é necessário se a definição vier depois.

#include<iostream>
using namespace std;

int fatorial(int n){   //primeiro a função
	...
}
int main(){            //depois a main
	...
}

PARÂMETRO Valor × referência

Por valor, a função recebe uma cópia. Para alterar o original, C++ oferece dois caminhos: ponteiro ou referência, com & no parâmetro.

void dobra (int x){ x = x*2; }   //nada muda 
void dobraP(int *x){ *x = *x*2; } //ponteiro  
void dobraR(int &x){ x = x*2; }   //referencia

dobra(v);    //v continua 5
dobraP(&v);  //v virou 10  
dobraR(v);   //v virou 20

PONTEIRO Os três símbolos

int *p declara. &x é o endereço de x. *p é o valor guardado nesse endereço. Ponteiro também serve para devolver mais de um resultado.

int x = 7;
int *p = &x;   //p aponta para x
*p = 9;        //x agora vale 9
p++;           //anda 1 int adiante

VETOR Já é um ponteiro

O nome do vetor é o endereço do primeiro elemento. Por isso soma(vetor,n) não leva &, e alterações dentro da função valem lá fora.

int soma(int v[], int n);   //identicos
int soma(int *v, int n);

soma(vetor,10);   //sem &
//v[i]  ==  *(v+i)

MATRIZ A 2ª dimensão é obrigatória

O compilador precisa saber o tamanho da linha para achar o endereço, e em C++ esse tamanho tem de ser constante. Declare um MAX e use só o quadrado de lado n.

const int MAX = 20;

int f(int m[][MAX], int n, int i);  //ok
//int g(int m[][],  int n);  ERRO
//int h(int n, int m[n][n]); nao e C++

RECURSÃO Duas partes, sempre

Caso base: quando parar e o que devolver. Chamada recursiva: resolve um pedacinho e chama a si mesma com o problema menor. Sem o base, estouro de pilha.

int fatorial(int n){
	if(n==0)//caso base ou trivial
		return 1;
	return n*fatorial(n-1);//chamada recursiva
}

A recursão em si não muda uma vírgula: caso base, chamada recursiva e índice de controle são idênticos nas duas linguagens. O que muda é a moldura em volta — entrada, saída e a declaração da matriz.

O truque que resolve a matriz sem laço: em vez de dois índices, use um contador linear pos que vai de 0 até n*n-1. A linha é pos/n e a coluna é pos%n. Uma única recursão varre a matriz inteira, indo de coluna em coluna e pulando de linha quando acaba — exatamente o percurso que o enunciado da Questão 4 da lista pede.

Os quatro tipos de função

func1.cpp

O programa da aula, com os quatro tipos numa tela só. Explique a diferença entre soma e mult — as duas calculam, mas só uma devolve.

#include<iostream>
#include<cstdlib>
#include<ctime>
using namespace std;

//1o tipo: nao recebe parametro e nao retorna valor
1 escreve(void){
	cout<<"Hoje e quinta feira"<<endl;
}
//2o tipo: recebe parametro do main e nao retorna valor
void soma(int a, int b){
	int s;
	s = a + b;
	cout<<"Soma de "<<a<<" + "<<b<<" = "<<s<<endl;
}
//3o tipo: recebe parametro do main e retorna valor p main
int mult(int a, int b){
	int m;
	m = a * b;
	2 m;
}
//4o tipo: nao recebe parametro do main mas retorna valor p main
int aleatorio(void){
	return(rand()%3);//faixa de 0 a 9
}
int main(){
	int x=3,y=5,mu,ale;
	srand(time(4));
	escreve();
	soma(y,x);

Gabarito

1void2return3104NULL5mult(x,y)

O que o código faz: demonstra os quatro tipos de função. Escreve uma frase, soma e imprime, multiplica e devolve, e sorteia um número de 0 a 9.

soma × mult: as duas recebem a e b e calculam. A diferença é o destino do resultado. soma é void: imprime ali mesmo e o valor se perde — a main não consegue reaproveitá-lo. mult é int: devolve o resultado com return, e por isso a main precisa de uma variável (mu) para guardar o que voltou. Guardar o valor é o que permite usá-lo depois numa conta, numa comparação ou noutra função.

void nos dois lugares: antes do nome significa "não devolve nada". Dentro dos parênteses, como em escreve(void), significa "não recebe nada" — em C++ também se pode deixar os parênteses vazios.

srand(time(NULL)): alimenta o sorteador com o relógio, para os números mudarem a cada execução. Sem ele, rand() devolve sempre a mesma sequência. Vai uma vez só, no início da main.

Nenhum protótipo: as quatro funções estão definidas antes da main, então o compilador já as conhece quando chega na chamada. Se você mover qualquer uma para depois da main, aí sim precisa declarar o protótipo no topo.

02

De iterativo para recursivo

fatit.cpp · fatrecurs.cpp

À esquerda o fatorial com while, à direita o mesmo fatorial em recursão. Explique o que, na versão recursiva, faz o papel do while.

//---------- versao iterativa (fatit.cpp) ----------
int fatorial(int n){
	int fat = 1;
	while(n>1){
		fat *= n;
		n--;
	}
	return fat;
}

//---------- versao recursiva: complete ----------
int fatorial(int n){
	if(n==1)//caso base ou trivial
		return 2;
	return n*fatorial(3);//chamada recursiva
}

int main(){
	int f,num;
	cout<<"Informe o valor ";
	cin>>num;
	f = fatorial(num);
	cout<<"Fatorial de "<<num<<" = "<<f;
}

Gabarito

10213n - 1

O que o código faz: lê um número e devolve o fatorial dele. As duas versões dão o mesmo resultado por caminhos diferentes.

Quem substitui o while: a própria chamada recursiva. No iterativo, a condição n>1 decide se repete e n-- faz o valor andar. No recursivo, o if(n==0) decide se para e o argumento n-1 faz o valor andar. É a mesma engrenagem — condição de parada e avanço — escrita de outro jeito.

Quem substitui a variável fat: ninguém. O acumulador desaparece: os produtos ficam guardados nas chamadas empilhadas e são multiplicados na volta — 4*(3*(2*(1*1))). Isso é o que se ganha e o que se paga na recursão: código mais curto, mas consumo de pilha proporcional a n.

Por que n==0 e não n==1: as duas param, mas n==0 também cobre fatorial(0), que por definição vale 1. Com n==1, chamar fatorial(0) passaria direto e a função desceria para −1, −2, −3… até estourar a pilha. Testar n<=1 resolve os dois de uma vez e é uma resposta igualmente aceitável.

Atenção ao tipo: int estoura em 13!. Se a prova pedir números maiores, use long long.

03

Potência sem usar pow

func1.cpp · exercício pendente

O exercício que ficou comentado no fim do func1.cpp: eleva(y,x) eleva a base y ao expoente x. Explique por que o caso base devolve 1 e não 0.

//eleva a base ao expoente sem utilizar o pow()
int eleva(int base, int expo){
	if(expo==1)//caso base ou trivial
		return 2;
	return base*eleva(base,3);//chamada recursiva
}

int main(){
	int x=3,y=5;
	cout<<y<<" elevado a "<<x<<" = "<<eleva(y,x)<<endl;
}

Gabarito

10213expo - 1

O que o código faz: calcula 5³ = 125 multiplicando a base por ela mesma, uma vez a cada chamada, até o expoente zerar.

O caso base devolve 1 por dois motivos que se encaixam: matematicamente, qualquer número elevado a 0 é 1; e 1 é o elemento neutro da multiplicação, então não estraga o produto que está sendo montado na volta. Devolver 0 zeraria tudo — 5*5*5*0 = 0.

Compare com a soma do vetor (Questão 4), onde o caso base devolve 0. A regra geral vale para qualquer recursão que acumula: o caso base devolve o neutro da operação. Soma e contagem → 0. Produto e potência → 1.

O que faz o problema diminuir: expo-1. A base fica igual em todas as chamadas; quem encolhe é o expoente. Passar expo sem o −1 seria recursão infinita.

O outro exercício pendente do arquivo — raiz(y) — não é recursivo: basta #include<cmath> e return sqrt(y); numa função do 3º tipo.

Soma dos elementos de um vetor

Lista · Questão 1

Preencher um vetor de 10 inteiros aleatórios de 0 a 9 e somar tudo com uma função recursiva. Explique qual é o caso base e por que a função precisa do índice i.

#include<iostream>
#include<cstdlib>
#include<ctime>
using namespace std;

const int TAM = 10;

int somaVetor(int v[], int n, int i){
	if(i1n)//caso base ou trivial
		return 2;
	return v[i]+somaVetor(v,n,3);//chamada recursiva
}

int main(){
	int vetor[TAM],s;
	srand(time(NULL));

	for(int i=0;i<TAM;i++)
		vetor[i] = rand()%4;//faixa de 0 a 9

	cout<<"Vetor: ";
	for(int i=0;i<TAM;i++)

	s = somaVetor(vetor,TAM,5);
	cout<<endl<<"Soma = "<<s<<endl;

Gabarito

1==203i + 141050

O que o código faz: sorteia 10 inteiros entre 0 e 9, mostra o vetor e devolve a soma de todos os elementos usando recursão.

Por que rand()%10: o resto da divisão por 10 só pode dar 0, 1, … 9 — exatamente a faixa pedida, e é a mesma linha que o professor usou na função aleatorio do func1.cpp. Para uma faixa de a a b: a + rand()%(b-a+1).

O índice i: é o parâmetro de controle. Sem laço, é ele que marca onde a varredura está; cada chamada avança uma posição. A primeira chamada parte de 0.

Caso base: quando i==n o índice passou do último elemento válido (n-1), não há mais nada para somar e a função devolve 0 — o neutro da soma. Devolver qualquer outro número estragaria o total.

Chamada recursiva: v[i]+somaVetor(v,n,i+1) soma o elemento atual com a soma de todo o resto. As chamadas empilham até o caso base e os valores vão sendo somados na volta: v[0]+(v[1]+(v[2]+…+0)).

Note a estrutura: é uma função do 3º tipo — recebe vetor, tamanho e índice, devolve um int que a main guarda em s. Igualzinho ao mult do func1.cpp, só que recursiva.

05

Maior elemento e sua primeira posição

Lista · Questão 2

15 números reais entre 12.3 e 25.7. A função recursiva devolve o índice do maior valor — e, em caso de empate, o da primeira ocorrência. Explique qual comparação garante isso.

const int TAM = 15;

int indiceDoMaior(float v[], int n, int i){
	if(i==1)//caso base: sobrou so o ultimo
		return i;

	int idxResto = indiceDoMaior(v,n,2);

	if(v[i]3v[idxResto])//empate fica com o atual
		return 4;

	return idxResto;
}

int main(){
	float vetor[TAM];
	int pos;
	srand(time(NULL));

	for(int i=0;i<TAM;i++)
		vetor[i] = 12.3 + ((float)rand()/RAND_MAX)*(5);

	pos = indiceDoMaior(vetor,TAM,6);

	cout<<fixed<<setprecision(2);
	cout<<"Maior = "<<vetor[pos]<<" na posicao "<<pos<<endl;
}

Gabarito

1n - 12i + 13>=4i525.7 - 12.360

O que o código faz: gera 15 reais na faixa pedida e descobre, recursivamente, o maior deles e a posição em que aparece pela primeira vez.

Por que devolver o índice e não o valor: o enunciado pede as duas informações. Devolvendo o índice você tem as duas de graça — o valor é vetor[pos]. Se a função devolvesse só o número, você precisaria de uma segunda varredura para achar a posição.

Caso base i==n-1: quando sobra um único elemento, ele é trivialmente o maior do pedaço que resta, então a função devolve o próprio índice.

A comparação >= é o coração da questão: a recursão resolve primeiro o pedaço da direita e só depois compara com o elemento atual, que está mais à esquerda. Com >=, o empate é resolvido a favor do índice menor, ou seja, da primeira ocorrência. Se estivesse >, o programa devolveria a última posição do maior valor e a questão estaria errada.

A faixa de reais: (float)rand()/RAND_MAX dá um número entre 0 e 1; multiplicado pela amplitude (25.7 − 12.3 = 13.4) e somado ao mínimo, cai dentro de [12.3, 25.7].

Não esqueça o #include<iomanip>: fixed e setprecision(2) vêm de lá e valem para todas as saídas seguintes — basta chamar uma vez.

Soma da diagonal principal

Lista · Questão 3a

Matriz quadrada de ordem digitada, valores inteiros de 4 a 12. Explique por que a segunda dimensão do parâmetro é MAX e não n.

const int MAX = 20;

int somaPrincipal(int m[][MAX], int n, int i){
	if(i==1)//caso base ou trivial
		return 2;
	return m[i][3]+somaPrincipal(m,n,4);//chamada recursiva
}

//--- na main: faixa de 4 a 12 ---
m[i][j] = 4 + rand()%5;

cout<<"Diagonal principal = "<<somaPrincipal(m,n,0)<<endl;

Gabarito

1n203i4i + 159

O que o código faz: percorre a diagonal principal — as casas em que linha e coluna são iguais — e devolve a soma desses elementos.

Um índice só: na diagonal principal, linha e coluna andam juntas. Por isso m[i][i], e por isso basta um parâmetro de controle em vez de dois.

Caso base i==n: a diagonal tem exatamente n elementos, dos índices 0 a n-1. Quando i chega em n, acabou: devolve 0.

Por que MAX e não n: para achar m[i][j] na memória o compilador calcula i*(tamanho da linha)+j, então precisa saber o tamanho da linha na hora de compilar. Como n só é conhecido quando o programa roda, C++ exige uma constante ali. A matriz é declarada com o teto MAX e o programa usa apenas o quadrado de lado n no canto superior esquerdo; n viaja como parâmetro comum, para a função saber onde parar.

A faixa 4 a 12: são 12 − 4 + 1 = 9 valores possíveis, então 4 + rand()%9.

07

Soma da diagonal secundária

Lista · Questão 3b

Mesma matriz, agora a outra diagonal. Uma única lacuna — e é a que mais derruba gente na prova. Explique como você chegou na fórmula da coluna.

int somaSecundaria(int m[][MAX], int n, int i){
	if(i==n)//caso base ou trivial
		return 0;
	return m[i][1]+somaSecundaria(m,n,i+1);
}

Gabarito

1n - 1 - i

O que o código faz: soma os elementos da diagonal secundária, a que desce da direita para a esquerda.

De onde sai a fórmula: escreva as posições para n=4 — (0,3), (1,2), (2,1), (3,0). Em todas, linha + coluna = 3, ou seja, i+j = n-1. Isolando: j = n-1-i.

Erro clássico: escrever n-i. Na primeira chamada, com i=0, isso daria a coluna n, que não faz parte do quadrado em uso — o programa lê lixo da memória e o resultado sai errado.

Detalhe de prova: se n for ímpar, o elemento do centro pertence às duas diagonais. Somar as duas e esperar o total da matriz não funciona: esse elemento é contado duas vezes.

Busca recursiva em uma matriz

Lista · Questão 4

Varrer a matriz inteira sem laço, contar quantas vezes o valor aparece e mostrar linha e coluna de cada ocorrência. Explique como um único índice percorre duas dimensões.

int buscaRecursiva(int m[][MAX], int n, int alvo, int pos){
	if(pos==1)//caso base: varreu tudo
		return 0;

	int linha  = pos2n;
	int coluna = pos3n;

	bool achou = (m[linha][coluna]==alvo);//true vale 1, false vale 0

	if(achou)
		cout<<"  encontrado em ("<<linha<<","<<coluna<<")"<<endl;

Gabarito

1n*n2/3%4achou5pos + 1

O que o código faz: percorre as n*n casas em uso da matriz, imprime a posição de cada ocorrência do valor procurado e devolve o total de ocorrências.

Índice linear: a matriz é tratada como se fosse um vetor de n*n posições. A casa número pos está na linha pos/n (divisão inteira: quantas linhas completas já passaram) e na coluna pos%n (o resto: quanto andou dentro da linha atual). Com n=5, pos=7 vira linha 1, coluna 2. É esse par de operações que dá o percurso pedido no enunciado — coluna a coluna, pulando para a próxima linha quando a atual acaba.

Contagem sem variável global: em C++, true convertido para inteiro vale 1 e false vale 0. Somando achou ao resultado da chamada seguinte, o total sobe sozinho na volta da recursão, sem contador externo nem ponteiro.

Mensagem de "não encontrado": quem decide isso é a main, olhando se o retorno foi 0. A função recursiva só conta — cada uma faz uma coisa, que é o que o enunciado pede ao mandar organizar o programa em funções.

Alternativa válida: usar dois índices, i e j, com a regra "se j==n, chama com (i+1,0)". Funciona igual, mas exige duas condições de parada em vez de uma.

Bloco D · ponteiros

09

Troca de valores com ponteiros

Ponteiros

A função clássica de troca. Explique o que aconteceria se os parâmetros fossem int a, int b.

void troca(int *a, int *b){
	int aux;
	aux = 1;
	*a  = 2;
	*b  = aux;
}

int main(){
	int x=10,y=20;
	troca(3,4);
	cout<<x<<" "<<y<<endl;//20 10
}

Gabarito

1*a2*b3&x4&y

O que o código faz: troca o conteúdo de duas variáveis da main, usando uma terceira variável auxiliar para não perder o primeiro valor.

Por que precisa de aux: se você escrevesse *a = *b direto, o valor original de a seria sobrescrito e não haveria como recuperá-lo.

Se fosse por valor: com int a, int b, a função receberia cópias. A troca aconteceria de verdade, mas só dentro da função — ao voltar para a main, x e y continuariam 10 e 20. É o exemplo canônico de por que ponteiro existe.

A versão C++ com referência: void troca(int &a, int &b) faz o mesmo sem * e sem & na chamada — escreve-se troca(x,y) e o corpo vira aux=a; a=b; b=aux;. Se a prova pedir ponteiros, use a de cima; saber apontar a diferença costuma valer ponto.

Dois resultados de uma vez

Ponteiros + recursão

Uma função void que acha o menor e o maior do vetor na mesma varredura recursiva. Explique como ela devolve dois valores sem ter return.

void minMax(int v[], int n, int i, int *menor, int *maior){
	if(i==n)//caso base: nada a fazer
		return;

	if(v[i]<1)
		*menor = v[i];

	if(v[i]>*maior)
		2 = v[i];

	minMax(v,n,3,menor,maior);//chamada recursiva
}

//--- na main ---
int menor=vetor[0],maior=vetor[0];
minMax(vetor,TAM,1,4,5);

Gabarito

1*menor2*maior3i + 14&menor5&maior

O que o código faz: varre o vetor uma única vez e atualiza, através de ponteiros, as variáveis menor e maior que vivem na main.

Dois resultados sem return: uma função devolve no máximo um valor pelo return. Quando precisa entregar dois ou mais, recebe ponteiros (ou referências) e escreve direto na memória de quem chamou. Pelos quatro tipos do func1.cpp, ela é do 2º tipo — recebe e não retorna — mas ainda assim entrega resultado.

Por que os dois começam em vetor[0]: inicializar com 0 quebraria com vetores só de negativos. Começando com um elemento real do vetor, a comparação sempre faz sentido. Por isso também a chamada parte do índice 1: o elemento 0 já foi considerado.

Cuidado com a lacuna 1: escrever v[i]<menor compararia um int com um endereço — o compilador reclama. Dentro da função, o valor é sempre *menor.

Soma do vetor andando com o ponteiro

Aritmética de ponteiros

A mesma soma da Questão 4, sem índice nenhum: quem anda é o ponteiro. Explique a diferença entre p+1 e *p+1.

int somaPtr(int *p, int n){
	if(n==0)//caso base ou trivial
		return 0;
	return 1+somaPtr(2,3);
}

//--- na main ---
cout<<"Soma = "<<somaPtr(vetor,TAM)<<endl;//sem &: vetor ja e endereco

Gabarito

1*p2p + 13n - 1

O que o código faz: soma n inteiros a partir do endereço p. Em vez de avançar um índice, avança o próprio ponteiro e diminui a quantidade que falta.

p+1 × *p+1: p+1 é o endereço do próximo inteiro — o compilador soma sizeof(int) bytes, não 1 byte. Já *p+1 é o valor apontado mais um. Trocar um pelo outro é erro de prova garantido.

Por que somaPtr(vetor,TAM) não leva &: o nome do vetor já é o endereço do primeiro elemento. vetor, &vetor[0] e o ponteiro p apontam para o mesmo lugar.

Equivalência útil: v[i] é literalmente *(v+i). As duas versões da soma — por índice e por ponteiro — fazem a mesma coisa; a prova pode pedir qualquer uma.

12

Inverter o vetor no lugar

Vetores + recursão

Dois índices caminhando um em direção ao outro. Explique por que o vetor sai invertido mesmo a função sendo void.

void inverte(int v[], int ini, int fim){
	if(ini>=1)//caso base: cruzaram
		return;

	int aux = v[ini];
	v[ini] = v[fim];
	v[fim] = aux;

	inverte(v,2,3);//chamada recursiva
}

//--- na main ---
inverte(vetor,0,4);

Gabarito

1fim2ini + 13fim - 14TAM - 1

O que o código faz: troca o primeiro com o último, o segundo com o penúltimo, e assim por diante, até os índices se encontrarem no meio. O vetor fica invertido sem precisar de um segundo vetor.

Caso base ini>=fim: cobre os dois finais possíveis. Com tamanho par, os índices se cruzam (ini>fim); com tamanho ímpar, eles se encontram no elemento do meio (ini==fim), que não precisa trocar de lugar com ninguém. Usar só ini==fim deixaria o caso par passar direto e a recursão sairia dos limites do vetor.

Void mas altera: o parâmetro int v[] é um ponteiro para o vetor original — não existe cópia. Toda escrita em v[ini] acontece na memória da main. É a mesma razão pela qual a Questão 9 precisou de & para inteiros simples: vetor já vai por referência, int não.

Último índice é TAM-1: um vetor de 10 posições vai de 0 a 9. Passar TAM acessa memória alheia.

Soma total da matriz com duas recursões

Matrizes

Uma função soma uma linha; a outra soma todas as linhas. Explique a diferença desta abordagem para a do índice linear da Questão 8.

int somaLinha(int m[][MAX], int n, int i, int j){
	if(j==n)//caso base: acabou a linha
		return 0;
	return m[i][j]+somaLinha(m,n,i,1);
}

int somaMatriz(int m[][MAX], int n, int i){
	if(i==n)//caso base: acabaram as linhas
		return 0;
	return somaLinha(m,n,i,2)+somaMatriz(m,n,3);
}

Gabarito

1j + 1203i + 1

O que o código faz: devolve a soma de todos os elementos da matriz. somaMatriz cuida das linhas, somaLinha cuida das colunas de uma linha.

Cada função tem seu caso base: somaLinha para quando j==n; somaMatriz para quando i==n. São duas recursões independentes, uma chamando a outra.

A lacuna 2 é a pegadinha: somaLinha precisa recomeçar do zero em cada linha nova. Passar j ou i ali faria a soma pular colunas.

Comparado ao índice linear: o pos/n e pos%n da Questão 8 resolve tudo numa função só, mas faz uma conta a cada chamada. A versão com duas funções é mais legível e aproveita a estrutura de linhas — útil quando você precisa de algo por linha (uma soma por linha, a média de cada linha). Ambas atendem à exigência de não usar laço.

14

Busca binária recursiva

Vetores + recursão

Busca em vetor ordenado. Explique por que ela só funciona com o vetor ordenado e o que devolve quando não acha.

int buscaBinaria(int v[], int ini, int fim, int chave){
	if(ini>fim)//caso base: faixa vazia
		return 1;

	int meio = (ini+fim)/2;

	if(v[meio]==chave)
		return 2;

	if(chave<v[meio])
		return buscaBinaria(v,ini,3,chave);

	return buscaBinaria(v,4,fim,chave);
}

Gabarito

1-12meio3meio - 14meio + 1

O que o código faz: procura chave olhando o elemento do meio e descartando metade do vetor a cada chamada. Devolve o índice onde encontrou, ou −1.

Por que precisa estar ordenado: a decisão de ir para a esquerda ou para a direita só é confiável se todos os elementos antes do meio forem menores e todos depois forem maiores. Em vetor desordenado, a metade descartada poderia conter a chave.

Por que −1: índices válidos vão de 0 para cima, então −1 é um valor impossível e serve como sinal de "não encontrado". Devolver 0 seria ambíguo — 0 é uma posição real.

Os ±1 importam: o elemento do meio já foi testado e não é a chave, então fica de fora das duas faixas seguintes. Escrever meio em vez de meio-1 faz a faixa nunca encolher quando a chave não existe — recursão infinita.

Ganho: a cada chamada o problema cai pela metade. Num vetor de 1000 posições, no máximo 10 chamadas; a busca linear faria 1000.

Só explique: o que este código faz?

Nada para completar. Leia, simule na mão com o valor sugerido, escreva a resposta e confira. É o segundo tipo de questão da prova.

T1

Simule com f(472)

int f(int n){
	if(n==0)
		return 0;
	return n%10+f(n/10);
}

Resposta

Soma os dígitos do número. n%10 extrai o último dígito, n/10 remove esse dígito. A recursão vai comendo o número pela direita até sobrar 0.

f(472) = 2 + f(47) = 2 + 7 + f(4) = 2 + 7 + 4 + f(0) = 13.

T2

Simule com g(10)

void g(int n){
	if(n==0)
		return;
	g(n/2);//chamada ANTES do cout
	cout<<n%2;
}

Resposta

Imprime o número em binário. g(10) escreve 1010.

O detalhe que a prova quer: o cout vem depois da chamada recursiva, então nada é impresso na ida — as chamadas empilham até n virar 0 e a impressão acontece na volta, invertendo a ordem dos restos. Se o cout viesse antes, sairia 0101, o binário de trás para frente.

T3

O que h devolve?

int h(int v[], int n, int i, int x){
	if(i==n)
		return 0;
	return (v[i]==x)+h(v,n,i+1,x);
}

Resposta

Conta quantas vezes o valor x aparece no vetor. A comparação (v[i]==x) devolve true ou false, que viram 1 e 0 na soma — então ela soma 1 a cada acerto.

É a mesma técnica da Questão 8, aplicada a um vetor em vez de matriz. Se devolver 0, o valor não está no vetor.

T4

O que acontece com a matriz?

void t(int m[][MAX], int n, int i, int j){
	if(i==n) return;
	if(j==n){ t(m,n,i+1,0); return; }

	if(i<j){
		int aux = m[i][j];
		m[i][j] = m[j][i];
		m[j][i] = aux;
	}
	t(m,n,i,j+1);
}

Resposta

Transpõe a matriz — troca linhas por colunas, refletindo tudo em torno da diagonal principal.

Dois detalhes valem ponto. O if(j==n) é o "pulo de linha": zera a coluna e avança a linha, o percurso sistemático que a Questão 4 da lista descreve. E o if(i<j) garante que cada par seja trocado uma única vez: sem ele, o par (0,1) seria trocado e depois destrocado em (1,0), e a matriz voltaria ao que era.

T5

O que é impresso?

void a(int x){ x = x*2; }
void b(int *x){ *x = *x*2; }
void c(int &x){ x = x*2; }

int main(){
	int v = 5;
	a(v);   cout<<v<<" ";
	b(&v);  cout<<v<<" ";
	c(v);   cout<<v<<endl;
}

Resposta

Imprime 5 10 20.

a recebe uma cópia de v: dobra a cópia, a cópia morre no fim da função e v continua 5. b recebe o endereço e *x = *x*2 escreve na própria variável da main, que passa a valer 10. c recebe uma referência — outro nome para a mesma variável — e chega ao mesmo resultado sem * nem & na chamada, dobrando para 20.

A pegadinha é a terceira: c(v) parece passagem por valor, mas o & na declaração do parâmetro muda tudo. Sempre olhe a assinatura da função, não a chamada.

05

Os erros que mais custam ponto

Cada um destes já apareceu em alguma questão acima. Passe os olhos na véspera.

  • Esquecer o caso baseA função chama a si mesma para sempre até a pilha estourar. Escreva o if de parada antes da chamada recursiva, sempre — e comente //caso base ou trivial, do jeito que o professor faz.
  • Caso base que nunca é alcançadoreturn n*fatorial(n); em vez de return n*fatorial(n-1); — o problema precisa diminuir a cada chamada.
  • Devolver o valor errado no caso baseSoma e contagem devolvem 0; produto e potência devolvem 1; busca que não achou devolve -1.
  • Função definida depois da main sem protótipoSe você seguir a ordem do professor — funções primeiro, main por último — nunca dá erro. Se inverter, declare int fatorial(int n); no topo.
  • Função int sem returnUm if com return e o resto do caminho sem nenhum devolve lixo. Toda saída possível da função precisa devolver algo.
  • Declarar a matriz com a ordem digitadacin>>n; int m[n][n]; não é C++ padrão — pode compilar no g++ e ser recusado na correção. Use const int MAX=20; int m[MAX][MAX]; e trabalhe só no quadrado de lado n.
  • Matriz sem a segunda dimensão no parâmetroint f(int m[][], int n) não compila. O certo é int f(int m[][MAX], int n, int i).
  • Colocar & no cinAo contrário do scanf do C, aqui é cin>>n;. E em vetor e matriz nada de & em lugar nenhum: somaVetor(vetor,TAM,0).
  • Confundir *p com pDentro da função, o valor é *menor; menor sozinho é o endereço. E p+1 anda uma posição, *p+1 soma um ao valor.
  • Estourar os limites do vetor ou da matrizUm vetor de 10 vai de 0 a 9. Diagonal secundária é n-1-i, nunca n-i.
  • Esquecer os #include<iostream> para cin/cout, <iomanip> para setw e setprecision, <cstdlib> para rand, <ctime> para time, <cmath> para sqrt.
  • Divisão inteira sem perceber5/2 vale 2, não 2.5. Isso é proposital em pos/n, mas vira erro numa média: use (float)soma/total.
  • Chamar srand(time(NULL)) dentro do laçoUma vez só, no começo da main. Dentro do laço, todos os sorteios saem iguais.
  • Laço dentro da função recursivaO enunciado proíbe. Se apareceu um for lá dentro, transforme o contador do laço em parâmetro da função — foi exatamente isso que aconteceu entre o fatit.cpp e o fatrecurs.cpp.
